01 // Flagship Substrate

Earthcall

A Person-centered ontology. An engine is attached to it — not the other way around.

“Unlike most of software history, Earthcall is built on a foundational conviction that all beings must be represented not by illusions hiding a teleologically indifferent operating system, but rather according to what they are — their actual, innate structure in reality.” — Earthcall Manifesto

Earthcall is not a game engine with philosophy in the docs. Domain nouns are not C++ classes. A tree is not a Tree. A robot is not a RobotEntity. Beings are authored in-world from primitives every other subsystem can see, then governed by Laws — runtime mathematical rules a Person writes, not hardcoded collisions wearing a story.

The top-level source tree is the ontology: Person, ConstructedBeing, Relation, Singularity, ZonesOfEarth, Identity. Adding a folder is an ontological claim.

People author behavior at runtime. Instead of shipping “move object X to Y,” Earthcall compiles through a Rete-style Law network expressed in OntoMath — one mathematical substrate for geometry, physics, and authored change.

Rendering is a modern WebGPU pipeline with a C++20 substrate, WASM, embedded React/Vite Person surface, and Python foreign IPC.

What exists in the system

Engineering evidence, not just a thesis.

Earthcall’s philosophy is implemented as concrete runtime machinery.

Runtime semantics

Laws + Rete-style evaluation

People author conditions and mathematical operations at runtime. The C++ substrate evaluates those Laws instead of forcing every behavior into a bespoke hardcoded path.

Identity & persistence

Stable beings across save → hydration

Identity, property paths, authored state, Persons, Zones, and dependencies are treated as first-class persistence problems rather than serialized afterthoughts.

Rendering & geometry

WebGPU, WGSL, SDFs, meshes

The vessel includes a modern GPU rendering path, authored geometry, implicit surfaces, spatial interaction, and the infrastructure needed to make ontology visible.

Person-facing authoring

Tools become part of the world

Creator tools, locomotion, selection, morphing, and other interactions are being moved toward First-Mover/Law semantics rather than remaining privileged UI exceptions.

Interop

Native, web, Python, foreign channels

C++20, embedded React/Vite, WASM, Python processes, and external systems meet through explicit interfaces instead of collapsing into one opaque application layer.

Engineering process

Tests, CI, review, and many agents

A multi-agent workflow is useful only when architecture remains coherent. Tests, bounded tasks, code review, and explicit invariants are how the project keeps many contributors aligned.

Load-Bearing Refusals

These are not style rules. They are the architecture.

No Domain Class

No Tree, Vehicle, or hardcoded entity classes. What a thing is is authored in-world.

The Tree is the Ontology

No arbitrary subsystem directories. Foreign hardware/software live under Singularity as channels.

Person Means Human

A Person is an actual human. Generative models are First Movers or Objects; they do not get a Body.

No Black Box

Every field a being carries is a registered property path. Unregistered is ungoverned.

Earthcall // Engineering Atlas

One system, many load-bearing layers.

Earthcall is not one renderer or one rule engine. It is an attempt to make ontology, identity, causality, persistence, geometry, authoring, and foreign-system integration agree with each other. These are the major systems currently carrying that architecture.

Implemented + verified

Prophetic Rete

Ahead-of-time analysis extracts Law read demands and write effects so irrelevant property changes can skip dirty-fact scanning. The analysis is deliberately allowed to be too broad, never too narrow; stale, incomplete, and foreign cases fail open.

Person-facing authoring

Laws as Runtime Programs

Laws carry serializable Condition and Action model trees, activation semantics, scope, registered PropertyPaths, and authored mathematical transforms. The long-term goal is to move behavior out of privileged engine exceptions and into things a Person can inspect and author.

Independent compute clock

Adaptive Compute / Slow Adapter

The expensive relevance learner does not get to own the render loop. Its independent clock performs bounded IMPROVE and REVISIT work over time, allowing expensive discovery to accumulate without turning every frame into a graph search.

Measured engineering

Architecture that survived contact with performance.

Some of Earthcall’s most important progress came from profiling an elegant idea, discovering where it was actually expensive, and changing the architecture instead of defending the abstraction.

~104 s → 0.4 ms

Field hydration

Moved SDF tessellation off Zone hydration. Fields become dirty on load and rebuild on first real consumer instead of blocking startup.

106.3 s → 2.7 s

Application startup

The same geometry-path redesign turned a macOS “not responding” launch into a bounded startup path.

105.7 s fail → 3.7 s pass

Frame-lag regression test

Performance became a guarded invariant: sub-quadratic frame cost, idle worlds do not spuriously fire Laws, and duplicate property registration is detected.

132–208 ms → ~14 ms

Vocabulary-index rebuild

Stopped asking every being about every indexed property name and stopped recollecting the name set once per Law per tick.

Generality test // Chess

Can the substrate author an application it was never taught?

Earthcall’s chess work became a stress test for the architecture: legality checks, turn order, captures, castling, promotion, check detection, interaction, persistence, and rendering had to be expressed through authored world state and Laws rather than a new ChessGame.cpp.

The value of that experiment is not “Earthcall can play chess.” It is that a concrete application forced the ontology, Law system, input channels, save model, and debugging surfaces to confront one another in the same world.

    03 // Engineering Depth

    The problems I like are the ones hiding between subsystems.

    The most valuable engineering work is often not a feature. It is finding the invariant that two independently reasonable systems accidentally violated.

    Identity

    Persistence without identity drift

    Runtime-authored worlds force identity to survive serialization, hydration, dependency closure, property lookup, and detached Zone loading. “Same name” is not the same thing as “same being.”

    Performance

    Keep expensive reasoning off the render clock

    When global search, adapters, diagnostics, or legacy simulation paths leak into every frame, the architecture is wrong. I look for ways to separate clocks, cache stable work, and make cost proportional to change.

    Abstraction

    Replace special cases with authored primitives

    Earthcall repeatedly asks whether a hardcoded behavior can become a Law, relation, property path, or other primitive that a Person can inspect and author instead of trusting an invisible engine exception.

    Integration

    Make boundaries explicit

    GPU ↔ CPU, C++ ↔ Python, native ↔ web, model ↔ robot, agent ↔ repository: the interesting bugs live at boundaries. I prefer typed contracts, observable state, and narrow interfaces over magical coupling.

    How I Judge a System

    01

    Model the Thing, Not the Convenience

    Useful abstractions simplify reality without quietly falsifying it. Names, ownership, identity, and boundaries should correspond to something real.

    02

    Prefer Generative Primitives

    A small set of strong primitives that compose is more powerful than an endless catalog of one-off features.

    03

    Human Authority Stays Human

    AI can search, draft, test, and implement at enormous scale. The person remains responsible for intent, architecture, judgment, and consequences.

    04

    Performance Is Architectural Feedback

    When the system is slow, I want to know which assumption made the work expensive — not merely which line can be micro-optimized.
